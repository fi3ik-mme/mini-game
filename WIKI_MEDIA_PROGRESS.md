## Як це працює

- Скрипт `scripts/enrich-wiki-media.mjs` читає JSON конкретної категорії, для кожного
  запитання витягує **ключове слово** (за замовчуванням — правильна відповідь, з обрізаними
  дужками й пунктуацією; для математики/мов — особливі правила).
- По ключовому слову робиться запит до Wikipedia REST API (`uk.wikipedia.org` / `en.wikipedia.org`
  / `es.wikipedia.org` залежно від мови предмета).
- Якщо стаття знайдена і має thumbnail — у `media` запитання спереду додається клікабельна
  картинка з посиланням на Вікіпедію. Існуючий SVG / емоджі залишається знизу.
- Скрипт **ідемпотентний**: запитання, в чию `media` вже вшита Вікіпедія (`*.wikipedia.org/wiki/`
  у HTML), пропускається. Запустиш повторно — не задублює.
- Усі звернення до API кешуються у `scripts/.wiki-cache/` (gitignored), щоб повторні прогони
  не били по API.
- Запуск: `node scripts/enrich-wiki-media.mjs <subject-id>` або без аргументів — пройдеться
  по всіх. Прапорець `--dry-run` друкує статистику, не змінюючи JSON.

Офіційні сайти (поза Вікіпедією) поки **не** скануються — для шкільних предметів це
малорелевантно, а парсинг довільних HTML-сайтів дуже ламкий. Якщо для конкретної категорії
це матиме сенс (наприклад, музеї чи музиканти з офіційними сторінками), додамо точкові
правила у фазах нижче.

## v3 (27.05.2026) — сутність запитання, не лише відповідь

Скрипт тепер визначає **тему питання** (Paint, Word, Windows, браузер…) і
для підпитань про інструменти в додатку посилається на сторінку програми,
а не на «олівець» / «гумка» / «заливка». Приклад: «Яким інструментом у Paint
малюють лінії?» → **Microsoft Paint**, не «Олівець».

Також: оцінка релевантності (`scoreArticle`) серед усіх кандидатів, а не
перший вдалий; відсікання статей-фільмів/персонажів у контексті ПЗ; аліаси
(`Paint` → `Microsoft Paint`, `процесор` → `Мікропроцесор`).

## Що змінилось у v2 скрипта

1. **Multi-candidate keyword extraction** — для українських предметів спершу
   пробує `correct answer`, потім «довгі» іменники з тексту запитання
   (proper-noun (mid-sentence Capital) → потім longest noun by length).
2. **Light Ukrainian morphology** — мала таблиця нормалізацій (`добі → доба`,
   `годин → година`, `місяців → місяць`, …) щоб уникнути false-positive типу
   «добі → Добі (Гаррі Поттер)».
3. **Article validation:**
   - відкидає disambig-сторінки;
   - відкидає статті, де description/extract починається з «фільм», «альбом»,
     «пісня», «персонаж», «герой серії», «вигаданий», … (та аналогічно en/es);
   - відкидає статті з заголовком на кшталт `Назва (1944)` або
     `Назва (фільм/корабель/село)` — Wikipedia так підставляє disambig-варіант
     коли «головної» статті без дужок не існує;
   - для коротких ключів (< 5 chars) додатково вимагає, щоб title статті
     перетинався з ключем;
   - відкидає матчі типу «село / селище / зупинка» для коротких ключів,
     якщо питання не про географію.
4. **`--force` flag** — дозволяє пере-обчислити вже вшиті матчі (наприклад
   після оновлення стоп-листу).
5. **Per-subject overrides** — `OVERRIDES[file][questionIndex] = { keyword|skip }`
   для known-bad випадків (наприклад STEAM[0..1] «Що означає STEAM?» — пропустити,
   бо «Science» матчиться на журнал, а ілюстрація STEAM не потрібна).

## Якість матчів

Скрипт намагається підібрати картинку автоматично, тож залишається ризик false-positive
випадків, коли коротке слово (наприклад «рівні», «коло», «село») у Wikipedia вказує на
нерелевантну статтю (фільм, населений пункт, тощо). Один такий випадок (`matematyka[59]`,
«рівні» → sci-fi фільм) прибрано вручну.

Якщо при перегляді гри зустрінеться ще така невдала картинка — її можна швидко прибрати:

```bash
node -e '\''
  const fs = require("fs"), p = require("path");
  const file = p.resolve("games/first-million/data/<subject>.json");
  const d = JSON.parse(fs.readFileSync(file, "utf8"));
  const q = d.questions[<index>];
  delete q.wikiKeyword; delete q.wikiTitle; delete q.wikiUrl;
  q.media = (q.media || "").replace(/^<a[^>]*wikipedia[^>]*>.*?<\/a>/, "");
  fs.writeFileSync(file, JSON.stringify(d, null, 2) + "\n");
'\''
```

## Легенда статусів

- ⏳ pending — ще не починалось
- 🚧 in progress — скрипт активно обробляє
- ✅ done — пройдено, медіа вмонтовано
- ⚠️ partial — є запитання, для яких Wikipedia нічого не знайшла (нормально, скрипт лишає оригінальну медіа)
